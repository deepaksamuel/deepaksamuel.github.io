Building (Particle Physics) Software

From source code to a working program, with CMake and make

What is source code?

A program begins life as plain text files written by people, in a language such as C++ or Python. This text is the source code. A file like DetectorConstruction.cc in Geant4 is source code: you can open it in vi and read it.

The computer cannot run C++ text directly. It runs machine code—binary instructions for its processor. Turning one into the other is called compiling, and the whole process of producing usable programs and libraries from source is called building.

Where is source code available?

Almost all particle physics software is open source: anyone may download, read, modify and build it.Particle physics packages publish their source openly:

  • Geant4 (detector simulation) — geant4.web.cern.ch/download, and on CERN’s GitLab.
  • ROOT (data analysis) — root.cern/install, and github.com/root-project/root.
  • CLHEP, Pythia, HepMC, Garfield++ and most others — on their project web pages, GitHub or GitLab.

Source code is usually distributed in one of two ways: as a compressed archive (a tarball, ending in .tar.gz), or as a git repository that you clone.

What compiling means

A compiler such as g++ reads source files and produces machine code. For a single file it is one command:

$ g++ hello.cc -o hello   # compile hello.cc into a program called hello
$ ./hello                 # run it

A library is compiled code meant to be used by other programs, e.g. libG4run.so. Files ending in .so are shared libraries; .h or .hh files are the headers that describe what a library contains.Real software is far bigger. Geant4 has thousands of source files that must be compiled in the right order, with the right options, and then linked together and with external libraries (for graphics, XML, mathematics…). Typing all of that by hand is impossible, which is why we use build tools.

What CMake does

Building is done in two stages, by two different tools:

  1. CMake configures the build. It inspects your machine—which compiler you have, which libraries are installed and where—checks that everything the software needs is present, and then writes a detailed set of build instructions called a Makefile.
  2. make reads the Makefile and actually runs the compiler on every file, then links the results into libraries and programs.

This is why CMake is called a build-system generator: it does not compile anything itself.CMake does not compile anything itself. Think of it as the planner, and make as the worker.

What is CMakeLists.txt?

CMake learns what to build from a file called CMakeLists.txt, written by the software’s authors and placed at the top of the source code (and often in sub-folders too). It lists the source files, the programs and libraries to create, and the external packages required. A minimal one looks like this:

cmake_minimum_required(VERSION 3.16)
project(Hello CXX)

add_executable(hello hello.cc)            # build program "hello" from hello.cc
install(TARGETS hello DESTINATION bin)    # where "make install" puts it

When you build Geant4 or ROOT you do not write CMakeLists.txt; you only point CMake at the folder that contains it. Its presence is how you know you are in the right place.

The three folders: src, build, install

In the exercises we always keep three separate folders side by side:

~/software/geant4/
├── src/       # the source code, with CMakeLists.txt at its top
├── build/     # where CMake and make do their work
└── install/   # the finished libraries, programs and headers
  • src holds the source code exactly as downloaded. We never edit or build inside it, so it stays clean.
  • build is a scratch workspace. CMake writes its Makefile and a file of settings called CMakeCache.txt here, and make fills it with thousands of intermediate files. If something goes badly wrong you can delete build and start again without re-downloading anything.
  • install receives the final product when you run make install: folders such as bin (programs), lib (libraries), include (headers) and share (data). This is what you actually use afterwards.

Building in a separate folder is called an out-of-source build. Geant4 refuses to build inside its own source folder.Keeping them apart means you can build several versions, or the same version with different options, from one copy of the source.

make -j4

By default make compiles one file at a time. Your computer, however, has several processor cores, each able to compile a file on its own. The -j option tells make how many jobs to run in parallel:

$ nproc      # how many cores do I have?
8
$ make -j4   # compile four files at the same time

If the build stops with Killed signal terminated program cc1plus, the machine ran out of memory. Run make again with a smaller number, e.g. make -j2.On four cores, make -j4 builds roughly four times faster; a Geant4 build that takes an hour on one core may take fifteen minutes. Do not exceed the number reported by nproc, and remember that each compile job of large C++ code can need 1–2 GB of memory.

If make is interrupted, simply run it again: it only recompiles what is not already done.

When something goes wrong, come back to the list of errors below.

Errors to expect, and how to fix them

When make fails, the useful message is the first error, often well above the last lines. Scroll up, or run make (without -j) so the output is not interleaved.Errors are normal, especially the first time on a new machine. Most of them mean that something the software needs is not installed. Read the message: it usually names what is missing.

Missing libraries during cmake

The most common case. CMake looks for a library, does not find it, and stops:

CMake Error at .../FindPackageHandleStandardArgs.cmake:230 (message):
  Could NOT find X11 (missing: X11_Xmu_INCLUDE_PATH X11_Xmu_LIB)

Here the Xmu library (part of the X11 graphics system) is missing. Install its development package and run cmake again:

$ sudo apt install libxmu-dev

Other messages and their usual fix:

Install the helper once with sudo apt install apt-file then sudo apt-file update. Searching the web for “ubuntu package for Xmu.h” also works.If the library is not in this table, ask the system which package provides the missing file:

$ apt-file search Xmu.h
libxmu-headers: /usr/include/X11/Xmu/Xmu.h

No compiler or no CMake

cmake: command not found
No CMAKE_CXX_COMPILER could be found.

Install the basic tools: sudo apt install build-essential cmake.

Wrong source folder

The source directory "/home/student/software/geant4" does not appear
to contain CMakeLists.txt.

CMake was pointed at the wrong place. Give it the folder that contains CMakeLists.txt, i.e. cmake ../src from inside build.

CMake version too old

CMake 3.16 or higher is required.  You are running version 3.10.2

Upgrade CMake (a newer Ubuntu release, or pip install cmake), or use an older version of the software.

Changes not taking effect

CMake remembers its earlier findings in build/CMakeCache.txt. If, after installing a missing package, it still complains, or if you change your mind about an option, empty the build folder and configure again:

$ cd ~/software/geant4/build
$ rm -rf ./*       # careful: only ever do this inside build
$ cmake ../src -DCMAKE_INSTALL_PREFIX=$HOME/software/geant4/install ...

Missing header during make

fatal error: X11/Xlib.h: No such file or directory

A header file belonging to a library is missing. The fix is the same as above: install the corresponding -dev package, then rerun cmake and make.

Out of memory during make

c++: fatal error: Killed signal terminated program cc1plus

Too many parallel jobs for the available memory. Use a smaller number, e.g. make -j2.

Permission denied during make install

CMake Error at cmake_install.cmake:46 (file):
  file INSTALL cannot copy file ... to "/usr/local/...": Permission denied.

You forgot -DCMAKE_INSTALL_PREFIX, so CMake tried to install into the system folder /usr/local. Reconfigure with the prefix pointing to your own install folder. Do not reach for sudo make install.

Library not found when running

./exampleB1: error while loading shared libraries: libG4Tree.so:
cannot open shared object file: No such file or directory

The program was built, but the shell cannot find the libraries at run time. You have not set up the environment in this terminal. Source the setup script: geant4.sh for Geant4 or thisroot.sh for ROOT (see the Geant4 and ROOT guides).

Could not find Geant4Config.cmake (or ROOTConfig.cmake)

When building your own code against Geant4, CMake cannot locate the installed package. Again, source the setup script first, or tell CMake explicitly: cmake .. -DGeant4_DIR=$HOME/software/geant4/install/lib/cmake/Geant4.
