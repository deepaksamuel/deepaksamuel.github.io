Building ROOT

Step-by-step instructions, from source code to your first histogram

ROOT is CERN’s framework for storing, analysing and plotting particle physics data, used from C++ and from Python. These steps build it from source. If the words source code, CMake, CMakeLists.txt or make -j4 are new to you, read Building (particle physics) software first.

Step by step

Replace the version number with the current one from root.cern/install/all_releases. Do each step in order, and check that it succeeded before moving on.

  1. Install the tools and required libraries

    sudo runs a command as the administrator and asks for your password. -dev packages contain the headers needed to build against a library, not just run it. The full list is at root.cern/install/dependencies.ROOT needs a compiler, CMake, the X11 graphics libraries and Python. On Ubuntu or Debian:

    $ sudo apt update
$ sudo apt install binutils cmake dpkg-dev g++ gcc git wget \
      libssl-dev libx11-dev libxext-dev libxft-dev libxpm-dev \
      python3 python3-dev python3-numpy libtbb-dev libvdt-dev libgif-dev

    These optional packages enable more features (OpenGL 3D viewer, fitting with GSL, FFTs, XML):

    $ sudo apt install libglu1-mesa-dev libglew-dev libftgl-dev \
      libgsl-dev libfftw3-dev libxml2-dev libpcre3-dev gfortran
  2. Create the three folders 
    $ mkdir -p ~/software/root
$ cd ~/software/root
$ mkdir src build install
$ ls
build  install  src
  3. Download the source code into src

    Download the source tarball and unpack it straight into src:

    $ wget https://root.cern/download/root_v6.32.08.source.tar.gz
$ tar -xzf root_v6.32.08.source.tar.gz -C src --strip-components=1

    --strip-components=1 drops the archive’s own top folder (root-6.32.08/) so the files land directly in src. Alternatively, clone with git: git clone --branch v6-32-08 --depth 1 https://github.com/root-project/root.git src.Check that CMakeLists.txt is there:

    $ ls src/CMakeLists.txt
src/CMakeLists.txt
  4. Go into the build folder 
    $ cd build

    Every remaining command, until the last step, is run from here.

  5. Configure with CMake

    If you use Anaconda or Miniconda, run conda deactivate first. Otherwise CMake may pick up conda’s Python and libraries, and the build fails in confusing ways.Tell CMake where the source is (../src) and where to install:

    $ cmake ../src \
      -DCMAKE_INSTALL_PREFIX=$HOME/software/root/install

    ROOT checks for many optional features and prints a summary of what is enabled. Success ends with:

    -- Configuring done
-- Generating done
-- Build files have been written to: /home/student/software/root/build

    Scroll up through the output and check that pyroot (Python support) is enabled; if it is not, python3-dev is missing. If you see CMake Error, read it carefully, fix the cause (see common errors) and run the same cmake command again.

  6. Compile with make 
    $ make -j4

    ROOT builds its own copy of the LLVM/Clang compiler for its C++ interpreter, Cling. This part is slow and memory-hungry; if the build is Killed, use make -j2.This is the long step, typically an hour or more at -j4. Progress is shown as a percentage. It has succeeded when it reaches [100%] with no line containing Error.

  7. Install 
    $ make install

    This copies the finished libraries, headers and programs into the install folder. Check:

    $ ls ../install
bin  cmake  config  etc  fonts  icons  include  lib  macros  man  README  tutorials  ...
  8. Set up the environment

    This must be done in every new terminal. To make it automatic, see the next step.Your shell does not yet know where ROOT lives. ROOT provides a script that sets PATH, LD_LIBRARY_PATH and PYTHONPATH:

    $ source ~/software/root/install/bin/thisroot.sh
$ root-config --version
6.32.08
  9. Make the setup permanent (optional)

    Use >> (append), never a single >, which would erase everything else in your .bashrc. Run the command only once.Instead of typing the source command in every new terminal, you can add it to your ~/.bashrc, a file that the terminal runs each time it starts (see what .bashrc does). Append the line with:

    $ echo 'source ~/software/root/install/bin/thisroot.sh' >> ~/.bashrc

    Check that it was added as the last line:

    $ tail -n 1 ~/.bashrc
source ~/software/root/install/bin/thisroot.sh

    Now open a new terminal (or run source ~/.bashrc) and check that ROOT is found without any setup:

    $ root-config --version
6.32.08

    Skip this step if you keep several versions of ROOT, or use conda, since an automatic setup can then pick the wrong one. To undo this, open ~/.bashrc in vi and delete the line.

  10. Test ROOT

    Start ROOT and draw a histogram of 10 000 Gaussian random numbers:

    $ root
root [0] TH1F h("h", "My first histogram", 100, -4, 4);
root [1] h.FillRandom("gaus", 10000);
root [2] h.Draw();
root [3] .q

    Commands starting with a dot are instructions to ROOT itself: .q quits, .x macro.C runs a macro.A window with a bell-shaped histogram should appear. Then check that Python can use ROOT:

    $ python3 -c "import ROOT; print(ROOT.gROOT.GetVersion())"
6.32/08

    If both work, your build is complete. The tutorials folder in install has hundreds of examples to try.

Problems specific to ROOT

The general errors in Building (particle physics) software all apply. In addition:

  • import ROOT fails with ModuleNotFoundError. Either you have not sourced thisroot.sh in this terminal, or ROOT was built without Python. Install python3-dev python3-numpy, empty the build folder and configure again.
  • import ROOT works in one Python but not another. ROOT only works with the Python it was built against. If you switched on conda after building, run conda deactivate.
  • CMake says a newer version of CMake is required. Recent ROOT releases need a recent CMake. Install it with pip install cmake, or use an older ROOT release.
  • No graphics window appears. On a remote machine, connect with ssh -X. Under WSL on Windows, use a recent WSL with graphics support.
  • The build uses all the memory and the computer freezes. Use fewer parallel jobs: make -j2.

The whole recipe

$ mkdir -p ~/software/root && cd ~/software/root
$ mkdir src build install
$ tar -xzf root_v6.32.08.source.tar.gz -C src --strip-components=1
$ cd build
$ cmake ../src -DCMAKE_INSTALL_PREFIX=$HOME/software/root/install
$ make -j4
$ make install
$ source ../install/bin/thisroot.sh

Download, configure, compile, install, set up—exactly as for Geant4.
